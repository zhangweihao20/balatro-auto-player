# 小丑牌（Balatro）自动打牌机器人

通过 [BalatroBot](https://github.com/coder/balatrobot) 的 JSON-RPC 接口驱动游戏，
不截图、不模拟鼠标键盘。机器人直接读取游戏状态、计算最优打法，再通过接口下发操作。

**当前状态：算分引擎与真机 100% 一致；出牌/弃牌决策已按策略规格重写为
参数化的评分函数，并提供调参工具。但胜率仍未达标**（最近一次实测 40 局
0 通关，平均底注 2.45）。原因和改进方向见[结果与诊断](#结果与诊断)。

> ⚠️ **最近一轮改动尚未在真机验证**：凑牌型规划的评分函数、参数化改造、
> 调参工具。当时运行环境无法启动游戏（提权被拒）。222 个单元测试全过，
> 但那不能替代真机校验——先跑一次 `tools\verify_scoring.py` 和
> `eval --games 20` 确认算分仍然逐手一致，再谈调参。

## 快速开始

游戏必须通过启动脚本运行，mod 才能拿到正确的环境变量。

```bat
:: 1) 启动游戏（会打开 Balatro 窗口，关掉它或 Ctrl+C 即结束）
tools\start_game.cmd

:: 2) 另开一个窗口，检查连接
tools\run_bot.cmd status

:: 3) 打一局 / 批量评测
tools\run_bot.cmd play
tools\run_bot.cmd eval --games 20
```

> 你的 PowerShell 执行策略是 `Restricted`，直接跑 `.ps1` 会被拒绝，
> 所以提供了 `.cmd` 包装器（内部用 `-ExecutionPolicy Bypass`）。

### 命令一览

| 命令 | 作用 |
| --- | --- |
| `status` | 检查游戏与 mod 是否就绪，打印当前局面 |
| `play` | 打一局（`--seed` 可复现） |
| `eval` | 批量跑固定种子，统计通关率（`--games N`） |
| `solve` | 对当前局面求解并打印候选打法，**不下发任何操作** |
| `watch` | 打开**决策日志窗口**（摆在游戏旁边，实时显示"做了什么、为什么"） |

常用参数：`--stake WHITE`、`--deck RED`、`--seed XXX`、`--discard-samples 32`、
`--journal runs\journal.jsonl`（决策日志路径，`--no-journal` 关闭）、
`--skip-blinds`、`--log-file runs\play.log`。

### 决策日志窗口

调试时最想知道的是"它为什么这样做"。机器人把每一步决策写成一行 JSON
（动作 + 理由 + 当时的数字），有**两个显示位置**——独立窗口，或者直接画在
游戏窗口右侧的面板（见 [`mod_additions/README.md`](mod_additions/README.md)）：

```bat
:: 一个窗口跑机器人（会同时写 runs\journal.jsonl 并推给游戏内面板）
.venv\Scripts\python.exe -m balatro_bot eval --games 30

:: 另一个窗口开独立日志栏（默认就读 runs\journal.jsonl）
.venv\Scripts\python.exe -m balatro_bot watch

:: 没跑游戏时先看看长什么样
.venv\Scripts\python.exe -m balatro_bot watch --demo
```

**独立窗口**默认置顶、摆在屏幕右侧；**游戏内面板**装好后自动出现（`F8` 隐藏）。
开关：`--no-mod-journal` 只关面板，`--no-journal` 只关文件。

两个位置按同一套动作类别上色：

| 颜色 | 动作 | 例子（理由 + 当时的数字） |
| --- | --- | --- |
| 绿 | 出牌 | `这一手就能过关（Pair 782 ≥ 需要 300）` 预估得分=782 需要=300 |
| 黄 | 弃牌 | `弃 3 张去凑 Flush：期望 1240 ≥ 现在 782 × (1+0.18)` 概率=26% |
| 蓝 | 购买 | `买 The Duo` 估值=6.5 门槛=4.5 阵容得分=×1.42 |
| 红 | 卖出 | `卖 #2 Throwback 换 Ice Cream` 边际贡献=201 阵容得分=×2.54 |
| 紫 | 重摇 | `重摇找换牌目标（牌位已满，只能换）` 预算=3 已摇=0 |
| 青 | 开包 | `从包里拿主牌型的星球牌` 拿了=Mercury 牌型=Pair |
| 橙 | 用牌 | `用星球牌 Mercury（升级 Pair）` 当前等级=3 |
| 灰 | 流程 | `离开商店：重摇预算用完（1/1）` 保留额=25 余额=21 |

设计要点：理由由**策略层在决策过程中就地记下**（`journal.note`），不是事后重算——
这样"日志里显示的数字"和"真正用于决策的数字"必然是同一个，不会漂移成两套逻辑。

## 工作原理

```
                 HTTP (JSON-RPC 2.0)
  游戏内 mod  ◄──────────────────────►  balatro_bot
  (Lua)                                 (Python)
     │                                     │
     │ gamestate()  完整局面                ├─ state.py    状态解析（带缓存）
     │ play/discard/buy/...  操作          ├─ cards.py    牌型判定 + 算分牌判定
     └─ 端口 12346                         ├─ scoring.py  一次出牌的算分
                                           ├─ jokers.py   小丑牌效果模型
                                           ├─ solver.py   最优出牌搜索
                                           ├─ strategy.py 出牌/弃牌/商店决策
                                           └─ bot.py      状态机主循环
```

### 关键设计

**只读状态、不猜状态。** 每一步都重新取一次 `gamestate()`，再决定下一步。
Balatro 有若干过渡状态（`HAND_PLAYED` / `DRAW_TO_HAND` / `*_PACK`），
与其预测流程，不如每轮问一次"现在是什么状态"。

**只有构成牌型的那几张牌算分。** 这是本作最容易搞错的地方，也是本项目
最关键的修正。游戏里算分循环遍历的是 `evaluate_poker_hand()` 给出的
`scoring_hand`，**不是打出的全部牌**：

| 牌型 | 算分牌数 |
| --- | --- |
| 对子 | 2 |
| 两对 | 4 |
| 三条 | 3 |
| 四条 | 4 |
| 顺子 / 同花 / 葫芦 / 五条 / 同花葫芦 / 同花五条 | 5 |
| 高牌 | **1**（只算 nominal 最高的那一张） |

所以"打一对 K 再配三张散牌"和"只打那两张 K"得分完全相同，垫牌不加分。
唯一例外是 Splash（"打出的每张牌都算分"）。

**小丑牌数值从游戏读，不靠猜。** 状态里的 `Card.effect` 是这张牌的当前
UI 描述文本，成长类小丑牌的当前值就在 `(Currently ...)` 段里。
解析时必须**优先取该段**——模板形如
`"+#1# Mult per hand played ... (Currently +#3# Mult)"`，
取到前一个数字会把 Green Joker 从 +11 变成 +1；对乘区类更是灾难，
Constellation 会从 `X1.8` 变成 `X0.1`（分数直接砍掉 95%）。
`tests/test_jokers.py` 专门钉住了这个陷阱。

**小丑牌 key 必须真实存在。** key 拼错不会报错，只会静默按 0 收益处理，
机器人于是持续低估自己的分数，而且从日志里完全看不出来。
`tools/extract_jokers.py` 直接从 `Balatro.exe`（LÖVE 融合包，源码 zip 附在
exe 末尾）里解析 `game.lua` 的 `P_CENTERS` 表，得到 **150 张小丑牌的权威定义**
（含 `rarity` / `cost` / `config` 精确数值），生成 `balatro_bot/joker_data.py`，
测试逐条校验模型表里的每个 key。这个机制上线时立刻抓出了 7 个拼错的 key。

## 策略参数体系

> **数学形式见 [`docs/strategy-math.md`](docs/strategy-math.md)** —— 全部决策规则
> 写成公式（纯文本 + Unicode，不依赖 LaTeX 渲染），并附**公式 → 代码位置**对照表。

策略规格的最后一条是"为每一项决策设置函数，通过不断地测试来修改参数以达到
通关目标"。代码按这个要求组织：**所有可调常数集中在 `balatro_bot/params.py`，
决策函数只读参数对象，不再散落魔法数字**。

### 出牌 / 弃牌决策

规格原文：

> 若最优牌型无法直接通关，则依据当前手牌、牌型倍率和牌库剩余卡牌策略性弃牌，
> 以获取**期望值**最高的牌型（凑出牌型的概率 + 需弃牌数量 + 牌型倍率，
> 其中弃牌数量为惩罚项）；并设置**弃牌厌恶程度**决定继续弃牌还是打出当前牌型。

实现在 `balatro_bot/planning.py`，分两层判断。

**第一层——凑哪个牌型**：

```
评分 = P^γ × log₂(1 + 目标牌型倍率 / 当前牌型倍率) − λ × 需弃牌数
```

- **P（凑出概率）用精确的超几何分布算**，不是蒙特卡洛采样：统计"还差几张、
  牌堆里还有几张能补上"，代入 `P(抽 d 张里至少中 k 张)`。无采样噪声且更快。
- **为什么不是纯加法形式**：规格里三项是相加的，但实测下
  "0% 概率的五条（基础分 1440）"会和"55% 概率的对子"打平甚至胜出——
  机器人会为了 6% 的同花顺**弃掉已经成型的顺子**。改成概率以幂次作用于
  倍率（这才是"期望值"该有的样子），并对倍率取 `log₂` 压缩
  （牌型基础分是重尾分布：高牌 5、五条 1440）。
- **γ 就是规格里"前期偏大牌型、中后期偏易凑牌型"那个参数**：
  γ<1 宽容低概率的大牌型，γ>1 要求稳定；按底注从 `gamma_early` 用 logistic
  过渡到 `gamma_late`，转折点是 `phase_pivot`。

**第二层——凑不凑**：把最佳计划换算成**期望得分**
（`P × 目标牌型得分 + (1−P) × 当前得分`；目标得分按基础分比例从当前实际得分
缩放，因此自动带上小丑牌和牌型等级），要求相对提升超过 `discard_aversion`
才真的弃牌。

**弃牌厌恶的初始值由机器自动生成**（`derive_initial_discard_aversion`）：
在标准 52 张牌上随机发 80 副手牌，统计"弃牌去凑"相对"现在就打"的期望提升
分布，取中位数的 35%，夹在 [0.05, 1.0]。评分公式或权重改了，初始值会自动
跟着变，不需要人工重调，之后再由调参工具继续修正。

### 调参

```bat
python tools\tune.py --list                                  :: 看参数与候选值
python tools\tune.py --games 12 --rounds 2                   :: 坐标下降
python tools\tune.py --param discard_aversion --values 0.05,0.2,0.5 --games 20
tools\run_bot.cmd eval --games 20 --set gamma_early=0.7 --set discard_aversion=0.3
```

一次只动一个参数，在候选值上各跑一遍评测，留最好的，再动下一个；
参数间的相互影响由 `--rounds` 补偿。**用同一批种子评测**，所以参数之间的
比较是配对的；排序依据是（通关数, 平均底注, 中位底注）。
最优参数写到 `runs/params.json`，之后用 `--params runs\params.json` 加载。

> 40 局评测约 12 分钟。先用 `--games 12` 粗调，再对少数有希望的参数细调。

## 结果与诊断

评测方式：`eval --games 40`，固定种子 `BOT000`–`BOT039`，红牌组 / 白难度，
决策过程确定性播种（同一种子必然复现同一局）。**同一组种子做配对比较**，
所以版本之间的差异不是种子运气造成的。

| 版本 | 平均底注 | 最高 | 死在第 1 底注 |
| --- | --- | --- | --- |
| 修正算分语义前 | 2.25 | 5 | — |
| 算分语义修正后 | 1.80 | 6 | 14/20 |
| 商店分类修正后 | 2.45 | 7 | 10/20 |
| —— 开始按 BalatroLLM 规则书改进 —— | | | |
| 规则落地前（基线） | 2.12 | 7 | **19/40** |
| + 小丑牌顺序 / 隐藏弃牌 / 盲注约束 / 利息与重摇预算 | 2.42 | 6 | 12/40 |
| + 牌型专精 / 开包选择 | 2.27 | 7 | 17/40 |
| **+ 纯功能牌压价（最终）** | **2.45** | 6 | **12/40** |

整体提升 **2.12 → 2.45（+16%）**，且**开局暴毙的局数从 19 降到 12**——
后一项比平均值更能说明问题：机器人早期生存能力确实变强了。

但**通关数仍然是 0**。

### 从 BalatroLLM 规则书落地的东西

`D:\balatrollm\src\balatrollm\strategies\*\STRATEGY.md.jinja` 是三份写给大模型的
完整规则书（default 730 行 / conservative 720 行 / aggressive 345 行），
`GAMESTATE.md.jinja` 描述状态字段。按它给出的"胜率影响排序"逐条落地：

| 报告排名 | 规则 | 落地情况 |
| --- | --- | --- |
| 1 | 小丑牌槽位顺序：加法在前、乘区在后 | ✅ 静态分类 + `rearrange` 免费重排 |
| 2 | 隐藏弃牌：打出的张数 = 补牌张数，尽量多打 | ✅ 同牌型内优先多打，垫牌挑最没用的 |
| 3 | 从底注 2 起守住 $25 吃满利息 | ✅ 牌型成型后启用（见下文取舍） |
| 5 | 专精一个牌型，星球牌只投它 | ✅ 星球牌与开包都按专精牌型选 |
| 7 | Boss 盲注针对性打法 | ✅ Psychic / Eye / Mouth / Flint / Ox / Tooth / Hook |
| 8 | 底注 4 起转向乘区牌 | ✅ 乘区牌估值加成 |
| 10 | 重摇预算：底注1 $10-15、底注2 $8-10 | ✅ 按底注递减 |
| 13 | 保留 1 次弃牌应急 | ⬜ 未落地 |
| 14 | 按阶段买补充包 | ✅ 星球包优先，幻灵包不买（我们不用幻灵牌） |
| 15 | 免费重排 + 有意选择垫牌 | ✅ 同 1、2 |

**其中三条是"规则理解错误"级别的问题，不修则分数系统性偏低：**

1. **只有构成牌型的那几张牌算分。** 垫牌不贡献点数，高牌只算最高那 1 张。
2. **得分是一个"运行中的倍率累加器"，不是 `chips × (基础+加法) × 乘区`。**
   加法牌在乘区牌右边时，它是在乘法**之后**才加进去的——顺序真的会改变分数。
3. **"包含对子"必须实现成一组谓词，而不是"最终牌型 == 对子"。**
   葫芦同时触发对子类和三条类小丑牌。

另外两条是"不修就会卡死"的：

4. **Boss 盲注的规则限制不会报错**——不满足限制的牌仍然可以打出，只是
   **不计分、不触发效果，等同于一次弃牌**。所以必须靠策略主动遵守。
   修之前，机器人在 The Psychic 下反复打出 2 张的对子，连丢 4 手直接输掉
   （这一点在 `tools/verify_scoring.py` 里留下了 4 条"预测有分、实际 0 分"的记录）。
5. **条件型乘区牌在回合第一手不触发**（例如 Card Sharp 要本回合重复牌型才 x3）。
   如果拿"这一手的分数有没有变高"当重排门槛，重排就永远不会发生。改成静态分类后
   才真正生效。

### 诊断：为什么还是打不通

底注分布显示 **12/40 的局死在第 1 底注**，其余大多死在 2–4。用
`play --seed BOT004 --verbose` 逐手复现（日志会打印每手的预测得分和差距）：

```
计划：Straight(5张)   chips=60 mult=4.0 x=1.000 → 240 ｜ 本轮还差 300 分
计划：Full House(5张) chips=54 mult=4.0 x=1.000 → 216 ｜ 本轮还差 600 分
```

问题在 **`x=1.000`**：小丑牌几乎全是加法类（实测终局阵容是
`Zany / Scary Face / Crazy / Raised Fist / Midas Mask` 这种 +mult 堆叠），
没有乘区引擎。底注 1 的 Boss 要 600 分，一手 216 × 4 手 = 864，稍微不顺就过不去。

**根因不是"不知道规则"，而是"不会做组合决策"。** 规则书里排第 5 的策略是
"选定一个牌型 → 星球牌升到 6 级以上 → 堆 xMult → 分数指数增长"。

这条已经部分落地：商店估值从**静态表**换成了**真实得分口径**（用同一个算分引擎
量每张牌的边际贡献，见 [`docs/strategy-math.md`](docs/strategy-math.md) §6），
牌型投资也已锁定在单一牌型上。**但实测仍然卡在同一处**：

```
对子等级投入（30 局合计）：+32 → +33 → +36 → +35   （四轮改动，基本持平）
即平均每局只有 1.2 级 —— 而对子要到第 3 级才能让 γ 越过切换点
```

**新的根因：瓶颈是"供给"而不是"判断"。**

| | 数值 | 结论 |
| --- | --- | --- |
| 天体包购买量 | 72 / 73 / 71 | 提高按需估值、紧急降门槛、供给券优先，**都没让它变多** |
| 包内命中率 | 33% → 38% → 39% | 买了 4 张 Telescope（保底命中 100%），聚合命中率只涨 1 个点 |
| 货架直售星球牌 | 5 / 5 / 5 | 买了 2 张 Planet Merchant（planet_rate ×2.4），数量不变 |

原因是**商店的出手位**：货架 2 格 + 补充包 2 格，星球牌要和 41 张塔罗、
小丑牌、代金券抢位；优惠券本身也要先出现在那 1 个券位里。提高"我们愿不愿意买"
或"单包命中率"都改不了**它出现多少次**。

所以下一步不应该继续调估值权重，而应该针对出手位本身：

1. **`Overstock` / `Overstock Plus`（+1 商店位）的优先级** —— 直接加宽出手位
2. **重摇** —— 但 Balatro 里重摇只换小丑/券，**不换补充包货架**，所以要确认
3. **接受这条路的上限** —— 若供给天花板确实压住了等级速度，就应改走
   不依赖牌型等级的得分路线（以乘区小丑牌为核心，等级只当辅助）

### 已排除的可能

- **不是算分不准**：真机逐手验证 39/39 完全一致（含 The Psychic 局面）
- **不是接口/状态机问题**：40 局 0 报错
- **不是性能问题**：一次出牌决策约 120–230 ms，整局 10–30 秒
- **不是规则理解偏差**：报告里的 15 条已落地 9 条，其余标注未做
- **不是环境问题**：牌型表、状态字段、卡牌字段都和文档一致

## 改进路线图

按预期收益排序。前三条都可以直接用 `eval` 量化（每轮约 12 分钟 / 40 局）。

1. **先跑通验证与调参闭环（当前最该做的）**
   最近一轮改动没在真机验证过。先 `tools\verify_scoring.py --games 4`
   确认算分仍逐手一致，再 `tools\tune.py --games 12 --rounds 2`
   让对局数据去定参数——这是规格里明确要求的那一步，也是现在唯一没跑的环节。

2. **组合估值，而不是单张牌估值**
   `JOKER_VALUE` 仍是静态表，`synergy_adjustment` 只处理了"牌型条件"这一类
   协同。应该推广成"和现有阵容的组合价值"：有 Blueprint 时 Baron 价值翻倍；
   有 Steel 牌时 Steel Joker 才值钱。数据基础已经具备（`joker_data.py` 有
   `rarity`/`config`，`jokers.py` 有每张牌的收益模型），进一步可以用现有的
   `Solver` 做前向模拟：假设买下这张牌，算一遍加入后的最优出牌得分。

3. **让牌型专精真正约束出牌**
   现在专精只影响买什么和"能过关时让 12% 的分"。应该让"专精牌型的等级"
   更深地进入出牌决策（累积 `played` 次数能提升部分小丑牌收益），
   并在离目标很远时优先做专精牌型的成牌。

4. **保留 1 次弃牌应急**
   规格没提，但 BalatroLLM 报告把它排第 13。注意这会和"隐藏弃牌"（多打牌）
   产生取舍，适合放进调参网格里试。

5. **Boss 盲注打法的细化**
   已覆盖 Psychic / Eye / Mouth / Flint / Ox / Tooth / Hook。还可补：
   The Arm（用等级最高的牌型，因为等级是**结算前**才降）、
   The Manacle（手牌上限 -1，规划 4 张手）、The Pillar（避开本 Ante 用过的牌）。

6. **经济节奏**
   利息是每 $5 给 $1、上限 $5（$25 吃满）。当前只在"已经有 3 张小丑牌"之后
   才启用 $25 下限——这是刻意的取舍：早期死守 $25 会让机器人买不起牌直接暴毙。
   这个阈值现在已经是可调参数，交给调参工具决定。

7. **跳过盲注换标签**
   已实现但默认关闭（`--skip-blinds`）。BalatroLLM 官方文档明确说"总是选盲注、
   从不跳过"是红牌组 / 白难度的合理基线，所以优先级不高。

### 一个更根本的方向

当前架构是"规则 + 参数化启发式 + 单步最优"。要达到稳定通关，通常需要
**前向搜索**：把"这一手打什么、下一手打什么、这次商店买什么"放进同一个搜索里
评估终局收益。项目的 `Solver` 已经把"给定状态求最优出牌"做成了便宜（约 3 ms）
且精确的可调用单元，`decision_rng` 保证可复现，评测循环 12 分钟一轮——
这三件事正是做搜索的前提条件。

## 已知限制

**建模边界**

- `j_four_fingers`（4 张即可成顺/同花）、`j_smeared`（红桃=方块）、
  `j_shortcut`（顺子可跳号）会改变**牌型判定**，当前未实现，列在
  `KNOWN_UNSUPPORTED` 里。买到它们时机器人的判断会偏差。
- `j_hiker` 给牌加的是**永久筹码**（`ability.perma_bonus`），mod 不单独暴露
  这个字段，所以带永久加成的牌会被略微低估。
- 少数成长类小丑牌（`j_obelisk`、`j_hitter` 等）依赖的状态没有暴露，
  按保守值处理——**低估比高估安全**，低估只会让机器人更保守。
- 幻灵牌（Spectral）刻意不使用：其中不少是破坏性的（整副牌变同点数但手牌上限
  -1、摧毁 5 张牌换钱），在没有完整评估之前不碰比乱用安全。

**方法边界**

- 弃牌决策在"期望值恰好卡在阈值附近"时会被蒙特卡洛噪声左右，
  表现为**弃牌张数**在采样数变化时摇摆（"打还是弃"这个判断是稳定的）。
  实际运行时采样数是固定的，且按局面确定性播种，所以同一局面必然复现同一决策。
  这是蒙特卡洛的固有限制，不值得靠堆采样数解决。
- 机器人不"偷看"牌堆顺序：`cards` 区域只给出组成，抽牌用随机采样模拟。

## 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| `连不上 http://127.0.0.1:12346` | 游戏没启动，或用 Steam 直接启动的（必须用 `tools\start_game.cmd`，mod 需要它设置环境变量） |
| `无法加载文件 ... 未对文件进行数字签名` | PowerShell 执行策略。用 `.cmd` 包装器，或加 `-ExecutionPolicy Bypass` |
| `uvx` 报 `拒绝访问` | uv 默认写 `%APPDATA%`。启动脚本已把 `UV_CACHE_DIR` / `UV_TOOL_DIR` 指到项目内 |
| 启动脚本报健康检查 30 秒超时 | **官方 CLI 的健康检查是硬编码 30 秒**（`manager.py` 的 `HEALTH_TIMEOUT`），而本机冷启动实测要 60~70 秒，于是 CLI 自己把刚起来的游戏杀了。默认启动方式已改成脚本直接启动 `Balatro.exe` 并自行轮询（超时 `-Timeout`，默认 240 秒）；要回到官方 CLI 路径用 `-ViaCli`（那时建议再跑一次，热启动通常够快） |
| 想确认算分准不准 | `python tools\verify_scoring.py --games 3` |
| 想知道当前局面会怎么打 | `tools\run_bot.cmd solve`（只打印，不下指令） |
| 决策太慢/太快 | `--discard-samples`（默认 32，越小越快越粗） |
