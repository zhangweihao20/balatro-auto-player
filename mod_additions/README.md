# 游戏内决策日志面板

把机器人的每一步决策（**做了什么 + 为什么**）画在 Balatro 游戏窗口**右侧**，
风格跟随游戏本身（深色面板、暖色描边、游戏内置字体、文字带阴影）。

这是本项目对 [balatrobot](https://github.com/) mod 的**附加**改动。之所以放在这里
而不是直接改 mod：mod 升级会覆盖 `balatrobot.lua`，需要能**重新应用**。

## 安装

**推荐用 PowerShell 版**——有些机器上安全软件会拦 `python.exe` 写 `%AppData%`
（本机实测如此：`python` 报 `PermissionError`，而 PowerShell 的 `Copy-Item`
和 cmd 的 `copy` 都能过），所以职责拆开：

```powershell
# 1) python 只写工作区：生成"打好补丁的入口文件"
.\.venv\Scripts\python.exe mod_additions\install.py --emit-entry

# 2) powershell 只做文件拷贝：把三个文件放进 mod 目录
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\mod_additions\install.ps1
```

**完全不用 python 的版本**（连第 1 步的产物都已备好）：

```
双击运行  mod_additions\install.cmd
```

如果 python 能写 `%AppData%`，也可以一步到位：

```bat
.venv\Scripts\python.exe mod_additions\install.py
```

其它用法：

```powershell
.\mod_additions\install.ps1 -Check        # 只检查状态
.\mod_additions\install.ps1 -Uninstall    # 卸载并还原
```

安装做的事（幂等，可重复运行）：

1. 拷贝两个新文件，**不动 mod 原有文件**：
   - `src/lua/ui/journal.lua` —— 面板绘制
   - `src/lua/endpoints/journal.lua` —— 接收决策的端点
2. 把 `%AppData%\Balatro\Mods\balatrobot\balatrobot.lua` 换成**打好补丁的版本**，
   改动是两处带标记的插入：加载并 `setup()` 面板模块、把 `journal.lua` 注册进
   `BB_ENDPOINTS`
3. 首次安装前把原文件备份成 `balatrobot.lua.bak-journal`

**装完重启游戏生效。**

## 用法

装好之后**什么都不用做**——正常跑机器人，面板自动出现在游戏窗口右侧：

```bat
.venv\Scripts\python.exe -m balatro_bot eval --games 5
```

- `F8` 显示 / 隐藏面板
- 面板每局开始时自动清空
- 不想推给面板：加 `--no-mod-journal`

面板和 `tools/decision_log.py` 的独立窗口**可以同时用**，两者读同一个来源，
互不影响。不想写 JSONL 文件就加 `--no-journal`。

## 数据流

```
strategy.py            决策时就地记下理由（journal.note）
      ↓
bot.py                 每步决策后取出理由 + 局面快照
      ↓
journal.py  ──┬──►  runs/journal.jsonl          ──► tools/decision_log.py（独立窗口）
              └──►  journal 端点（mod）          ──► 游戏内面板
```

两条出口是**尽力而为**的关系：面板没装、端点报错、mod 崩了，都只会提示一次，
绝不会影响对局。

## 面板长什么样

```
┌────────────────────────────────────────────┐
│  底注 5    第 14 回合                 $21   │  ← 标题条（游戏的红底 + 金色金额）
│  还差 6528   本关已得 9972   出牌 1  弃牌 4 │
├────────────────────────────────────────────┤
│ ▌22:15:04  弃牌                            │  ← 左侧色条按动作类别上色
│   弃 4 张去凑 Straight Flush：期望 379 ≥    │
│   现在 72 × (1+0.00)                       │
│   概率=38%  凑成分=1000  期望=379  危急=1.0x│  ← 数字暗一档
│ ────────────────────────────────────────── │
│ ▌22:15:05  出牌                            │
│   已成牌（High Card）→ 直接打               │
│   牌型=High Card  预估得分=15  够过关=False │
└────────────────────────────────────────────┘
```

配色按动作类别（和独立窗口同一套语义）：

| 颜色 | 类别 | | 颜色 | 类别 |
| --- | --- | --- | --- | --- |
| 绿 | 出牌 `play` | | 青 | 开包 `pack` |
| 黄 | 弃牌 `discard` | | 橙 | 用牌 `use` |
| 蓝 | 购买 `buy` | | 浅绿 | 重排 `rearrange` |
| 红 | 卖出 `sell` | | 灰白 | 盲注 `blind` |
| 紫 | 重摇 `reroll` | | 灰 | 流程 `flow` |

**风格对齐的几点做法**：

- 颜色优先从游戏自己的调色板取（`G.C.*`），取不到才用兜底值 —— 游戏改版换色时面板跟着变
- 字体用 `G.LANG.font.FONT`（当前语言的字体，中文环境下带 CJK 字形），
  而不是自己加载字体文件（字体打包在 `Balatro.exe` 里，拿不到）
- 文字带黑色偏移阴影，和游戏里的文字处理一致
- 面板画在 `love.draw` 之后，先 `love.graphics.origin()` / `setShader()` 复位变换，
  否则会跟着游戏的画布缩放跑到画面外
- 布局**自底向上**：从最新一条往回量高度，最新决策永远贴在底部

## 调试路上踩的三个坑（都写在代码注释里了）

**① 字号必须按窗口定标，不能直接给一个小数。**
游戏的字体是按**很大的像素尺寸**加载的——实测 `font:getHeight() = 203`，
内部再乘 `FONTSCALE = 0.12`、`TILESCALE = 4.465` 和画布缩放。而我们的面板画在
**窗口像素坐标系**里，所以第一版直接传 `scale = 0.72` 的结果是文字 146px、
糊满半屏。

**② 字体必须按目标字号"新建"，不能把游戏那个缩小。**
缩小 11 倍会走 LÖVE 的线性过滤，字会发虚（用户实测反馈"字体太模糊"）。
字体描述表里有 `file` 字段（实测 `resources/fonts/NotoSansSC-Bold.ttf`，
中文用思源黑体），所以现在**用同一个字体文件按目标像素高度新建一个字体，
再以 `scale = 1` 绘制**——字形直接按最终尺寸栅格化，天然清晰。
注意字体行高和字号不是 1:1（实测 size=140 → height=203），要按实测比例修正一次。

**③ 换行必须"自己折、自己画"，不能 `getWrap` 量 + `printf` 画。**
两者在**中文**下的换行规则不一致：中文没有空格，`printf` 会在字符间断行，
而 `getWrap` 报的是按"词"算的行数。于是量出来的高度比画出来的小，
多行文字越叠越密（实测整片糊在一起）。现在用自带的 UTF-8 拆分函数按字符折行，
**量多少就画多少**，折行结果按宽度缓存在记录上，不会每帧重算。

## 面板不遮挡游戏内容（重要）

面板**不是浮在游戏上面的**，而是占一条**真正的空白**。做法是让游戏以为窗口比实际窄
`reserve` 像素：

```lua
local game_resize = love.resize
love.resize = function(w, h)
  return game_resize(w - reserve, h)   -- 游戏按窄窗口布局：内容靠左，画布也只建那么宽
end
```

游戏的一切布局都由 `love.resize(w, h)` 的 `w` 推导（`G.TILESCALE`、`G.ROOM.T.x`、
`G.CANVAS` 的尺寸、以及最后那句 `draw(self.CANVAS, 0, 0)`），所以谎报宽度之后，
游戏会把内容排在左侧，画布右侧就空出来了——面板画在那里，**一点都不压到游戏**。

**两个关键性质**（都是实测确认的，不是推断）：

1. 游戏是**按高度充满**的（窗口比 `WINDOWTRANS` 的宽高比更宽时走 else 分支），
   所以 `TILESCALE` 只由高度决定 —— **加宽窗口不会让游戏变大或变小**；
2. 画布仍 1:1 贴在屏幕原点，像素比例没变，所以**鼠标拾取不需要任何补偿**，
   手动玩也不受影响。

### 空间从哪来

内容宽度是定值（实测 1965px），2048 宽的窗口左右各只剩 42px，根本不够。
所以面板会**先把窗口加宽**到"内容 + 两侧留边 + 面板"够用的尺寸：

```
2048 → 2413  (= 1965 内容 + 48 留边 + 400 面板)
```

**加宽只让游戏两侧的空白变多，游戏本身不变。** 上限是屏幕宽度。

### 三条安全界线

让出宽度前会检查，任一不满足就少让一点（宁可面板窄，也不破坏游戏）：

| 界线 | 为什么 |
| --- | --- |
| 不超过 `w - 自然内容宽` | 一旦越过，游戏会改走"按宽度充满"分支、`TILESCALE` 变小 → **整个游戏缩水** |
| 内容两侧各留 `min_side=24` | 保证内容不会被画布切掉 |
| 不超过 `reserve_w=400` | 面板够用就行 |

**这里有个坑值得记下来**：算"自然内容宽"时**不能读 `G.TILESCALE`**——读到的会是
上一次谎报之后的缩水值，于是内容宽算小 → 让出更多 → 游戏更小 …… 形成反馈回路，
游戏会被一路挤小。第一版就是这么写的，实测内容宽从 1965 掉到 1606。
现在按游戏自己的原式重算（`main.lua:330-334`，用 `G.window_prev`）：

```
w/h < orig_ratio  →  scale = orig_scale * w / prev.w
否则              →  scale = orig_scale * h / prev.h
```

### 另一条：动窗口必须等第一帧

mod 是在 **LÖVE 初始化之前**加载的，那时 `love.window` / `love.graphics` 还不能用。
在 `setup()` 里直接动窗口会把游戏崩掉，**连启动都完不成**（Lovely 日志只到
`Initialization complete`，进程直接消失）。所以窗口相关的操作全部推迟到第一帧。

`F8` 隐藏面板后，那条空白仍然留着（不还原窗口尺寸）——还原会引入额外风险，
而留白只是看着空一点。


面板启动时会把量到的字体度量打进 mod 日志（`BB.JOURNAL` 一条），
换分辨率 / 换语言后可以直接看它来核对：

```
journal metrics: win=2413x1152 bodyH=25 headH=32 scale=1.000
                 file=resources/fonts/NotoSansSC-Bold.ttf gameFontH=203
```

## 布局要点

- **不遮挡游戏内容**：面板占一条真正的空白（见上一节），不是浮在游戏上面
- **从上往下**排：记录少的时候整块贴在顶部，装满之后最老的从顶部滚出、
  最新的仍停在底部（用户反馈"初始内容应该从顶部开始生成"）
- 正文 **25px**、标题 **32px**（窗口高度的 1/46）——**自建字体、以 scale=1 绘制**，
  清晰不发虚
- 时间用暗一档的灰、类别徽标按动作上色、理由用白色、数字用类别色 0.85 透明度
- 左侧一道 3px 类别色条，比整行铺色克制，不抢游戏本身的视觉
- `F8` 显示 / 隐藏

### 字号 ↔ 信息量：一个旋钮

面板宽度是固定的 400px（那条空白的宽度），所以**字号一大，一屏能看的条数就少**。
这是刻意的取舍，旋钮在 `src/lua/ui/journal.lua`：

```lua
local BODY_HEIGHT_DIVISOR = 46   -- 正文高度 ≈ 窗口高 / 这个数
local HEAD_SCALE = 1.28          -- 标题 = 正文 × 这个数
```

| 值 | 正文（1152p） | 一屏约几条 |
| --- | --- | --- |
| `62` | 17px | ~20 |
| **`46`（当前）** | **25px** | **~9** |
| `38` | 30px | ~7 |

调小 = 字更大、条数更少。条数变少只会让**最老的记录从顶部滚出去**，
不会截断任何一条——布局本来就是"从下往上量、从上往下排"的。

标题栏高度是**跟着字体算**的（`header_height()`），不是写死的常量——
否则一改字号就会把两行标题挤在一起。

## 已知限制

- **mod 升级会覆盖 `balatrobot.lua`**，需要重新跑一次 `install.py`（两个新文件也可能被清掉）
- 面板只在牌局中显示（`G.STAGE == G.STAGES.RUN`）
- 面板出错时会**自动关闭自己**并在 mod 日志里留一条，不会把游戏搞崩
- 面板不接管输入，只有 `F8` 会被吃掉
- 会自动把游戏窗口加宽到 2413×1152（屏幕不够宽时少加宽一点）；
  想关掉就改 `src/lua/ui/journal.lua` 里的 `BB_JOURNAL.auto_widen = false`
- `F8` 隐藏面板后那条空白仍留着（不还原窗口尺寸——还原会引入额外风险）
