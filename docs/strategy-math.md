# 策略数学表述

本文把 `balatro_bot` 的全部决策规则写成数学形式：哪些量是**由算分引擎派生**的、
哪些是**自动标定**的、哪些是**人工常数**。

> **为什么不用 LaTeX。**
> 本项目的文档会被各种客户端（终端、编辑器预览、GUI）读取，而 `$$…$$` 与
> `\frac` `\binom` 这类命令在不支持数学渲染的环境里会显示成反斜杠乱码。
> 所以本文一律使用 **纯文本 + Unicode 数学符号**，并放在代码块里（预格式化，
> 任何环境都不会走样）。符号约定见 §13。

## §0 记号

```text
x            完整局面（状态向量）
H, D, J      手牌、牌堆、小丑牌序列 J = (j₁, …, j_m)
a, r         底注、回合序号
ℓ : T → N    牌型等级表（T = 牌型集合）
τ ∈ T        牌型名
R            本关剩余需求分
h_L, d_L     剩余出牌数、剩余弃牌数
M            金钱
S_cur        当前能打出的最高分
Φ_S(x)       得分能力（§5）
T_allowed    当前 Boss 盲注允许的牌型（§11）
```

## §1 计分泛函 S

一切的地基。已通过真机逐手验证（`tools/verify_scoring.py`，22/22 完全一致）。

```text
基础分（牌型等级 ℓ(τ)）:
    c₀(τ, ℓ) = c_s(τ) + c_ℓ(τ) · (ℓ(τ) − 1)
    m₀(τ, ℓ) = max( m_s(τ) + m_ℓ(τ) · (ℓ(τ) − 1),  1 )

       c_s, m_s  一级基础筹码/倍率（BASE_HAND_SCORE，12 个牌型实测校准）
       c_ℓ, m_ℓ  每级增量（HAND_LEVEL_STEP，从游戏源码导出）

计分牌集 A(P) ⊆ P        （由牌型判定给出，只有这些牌贡献牌面分）
牌面求和:
    C_card(P) = Σ_{i ∈ A(P)} c(i)
    M_card(P) = Σ_{i ∈ A(P)} m(i)
    X_card(P) = Π_{i ∈ A(P)} x(i)

小丑牌折叠, k = 1 … m:
    (c⁽⁰⁾, m⁽⁰⁾) = ( c₀ + C_card ,  (m₀ + M_card) · X_card )
    (c⁽ᵏ⁾, m⁽ᵏ⁾) = ( c⁽ᵏ⁻¹⁾ + α_k ,  (m⁽ᵏ⁻¹⁾ + β_k) · ξ_k )

    (α_k, β_k, ξ_k) = E(j_k)                       第 k 张小丑牌的效果三元组
    debuff(j_k) = 真  ⟹  (α_k, β_k, ξ_k) = (0, 0, 1)   被 Boss 禁用则不结算

    ┌──────────────────────────────────────┐
    │   S(P, J) = ⌊ c⁽ᵐ⁾ · m⁽ᵐ⁾ ⌋           │
    └──────────────────────────────────────┘
```

**加乘交替 ⟹ 槽位顺序影响得分**：加法牌放左边、乘区牌放右边才能拿满。
`Solver` 利用这个性质搜索最优摆放（`best_joker_order`）。

## §2 凑牌计划的评分 V

```text
命中概率（精确超几何尾概率, N = |D| 牌堆张数）:

                  min(o_τ, d_τ)    C(o_τ, k) · C(N − o_τ, d_τ − k)
      P_τ  =        Σ               ───────────────────────────────
                    k = n_τ                   C(N, d_τ)

        n_τ  还缺几张才能凑成
        o_τ  牌堆里能补上缺口的张数（"补牌"）
        d_τ  这个计划要弃几张

凑成后的实际得分（**含当前小丑牌效果**）:
      C_τ = S( P̃_τ ∪ K_τ , J )        P̃_τ = 造出的补牌, K_τ = 保留的牌

未凑成时的残余牌力（不能拿 S_cur 兜底: 牌已经弃掉了）:
      M_τ = max_{P ⊆ K_τ} S(P, J)

      ┌────────────────────────────────────────────────────────────┐
      │  V(τ) = P_τ^γ · log₂( 1 + C_τ / S_cur )  +  β · d_τ          │
      │         ╰─概率─╯   ╰──得分倍率（含小丑效果）──╯   ╰弃牌(正号)╯  │
      └────────────────────────────────────────────────────────────┘

      τ* = arg max_{τ ∈ T_allowed} V(τ)
```

**形状的三点理由**（都是实测踩出来的）：

| 取法 | 理由 |
| --- | --- |
| 概率取**幂** `P^γ` 而非并列相加 | 纯加法下"0% 的五条"会和"55% 的对子"打平，实测导致为 6% 的同花顺**弃掉成型的顺子** |
| 对得分取 `log₂` | 牌型基础分是重尾分布（高牌 5 / 五条 1440），线性比值让罕见牌型一枝独秀 |
| `β` 取**正号** | 规格："弃牌数量不再是惩罚项"。Balatro 里补牌数 = 弃牌数，多弃一张就是多循环一张 |

## §3 打 / 弃判定

```text
      E_τ = P_τ · C_τ + (1 − P_τ) · M_τ               期望得分

      ┌────────────────────────────────────────────────┐
      │  弃牌  ⟺  E_{τ*}  ≥  S_cur · (1 + θ)            │
      └────────────────────────────────────────────────┘

           ⎧ 0    若 0 < h_L ≤ d_L      （经济规则：弃牌数追平出牌数就把不值钱的弃牌花掉）
      θ =  ⎨ 0    若 κ > 1              （危急：稳扎稳打已无意义）
           ⎩ α    否则                   α = discard_aversion

危急时另有一条改写：E 换成 P_τ* · C_τ*（把"没凑成还能打多少"剔除——
那点分救不了这一关）。
```

## §4 前后期自适应 γ

规格原文：「**当牌型的期望值超出一般高难度牌型时可切换出牌策略**」——
所以切换依据**不是底注**，而是专精牌型的得分有没有追平一般高难度牌型。

```text
      ρ      = b(τ*, ℓ) / B                          B = 一般高难度牌型基础分参考
      share  = σ( (ρ − s₀) / s₁ )                    σ(z) = 1 / (1 + e^(−z))

      ┌──────────────────────────────────────────────────┐
      │   γ = γ₀ + (γ₁ − γ₀) · share                      │
      └──────────────────────────────────────────────────┘

      γ₀ = 0.55     γ₁ = 1.45     s₀ = 0.8     s₁ = 0.25     B = 140

      对子为例:
        等级ℓ   基础分b     ρ        share      γ
          1       20      0.143     0.066     0.609     ← 前期：继续追大牌型
          2       75      0.536     0.190     0.721
          3      160      1.143     0.797     1.267     ← 已切换
          4      275      1.964     0.990     1.441     ← 中后期：稳定做小牌型
```

**星球牌与对应小丑牌把专精牌型喂起来之后，策略自动切换**，不需要人工指定第几底注。

## §5 局面泛函

```text
得分能力:

      ⎧ max_{P ⊆ H} S(P, J)                   若 H ≠ ∅      （出牌阶段：真实手牌求最优）
Φ_S = ⎨
      ⎩ max_{s ∈ Scen} L( J, s, τ* )          否则          （商店阶段：代表性手牌 × 阵容）

危急度（"就算每手都打最优也过不了这一关"）:
      ┌─────────────────────────────────────────────────┐
      │   κ(x) = R / ( Φ_S(x) · max(1, h_L) )            │
      └─────────────────────────────────────────────────┘

进度（时间维度）:
      ┌─────────────────────────────────────────────────┐
      │   π(x) = Φ_S(x) / ( N₈ · g^(−(8 − a)) )          │
      └─────────────────────────────────────────────────┘

      N₈ = 50000（第 8 底注需求）    g = (50000/300)^(1/7) = 2.0769

      N₈ · g^(−(8−a)) 的含义：**按"每底注涨 2.08 倍"的速度，现在本该达到的水平**

紧急判据:
      u(x) = 1[ Φ_S > 0  且  ( π < 1  或  κ > 1 ) ]

需求曲线（game.lua 的 get_blind_amount，白注）:
      A1..A8 = 300, 800, 2000, 5000, 11000, 20000, 35000, 50000
      同一底注内: 小盲 = N, 大盲 = 1.5N, Boss = 2N
```

紧急/落后时解除保守（§9）：利息保留额归零、重摇预算改成"花得起就一直摇"、
换牌门槛归零、专精星球牌加权。

## §6 阵容泛函与边际

```text
阵容得分:
      L(J) = max_{σ ∈ Π(J)} S( P*, J_σ )          P* = 代表性手牌(τ*)

      Π(J) = J 的全部槽位排列          （机器人每回合可免费重排）

边际贡献（"哪张最该卖"的正确依据）:
      Δ_j = L(J) − L( J \ {j} )

      j*_sell = arg min_{ j : 非永恒(j) }  Δ_j

换入增益（"这张值不值得换进来"）:
      g⁺(c)   = max_i   L( J ⊕_i c ) / L(J)
      g⁻(c,i) = max_i'  L( (J \ {i}) ⊕_i' c ) / L(J)

      买入  ⟺  g⁺(c) ≥ 1 + δ_b
      换牌  ⟺  g⁻(c, j*_sell) ≥ 1 + δ_s

      δ_b = joker_buy_gain  = 0.05
      δ_s = joker_swap_gain = 0.08        u = 1 ⟹ δ_s := 0
```

**为什么必须搜摆放位置**：`Blueprint` 复制的是右边那张，追加在末尾等于什么都没复制
（实测被估成 ×1.0，按最佳摆放是 ×2.0）。

**为什么必须用真实得分而不是静态表**：静态表看不出两张牌一起才成立的效果，也看不出
算分引擎压根不认某些牌。实测错误包括：

- 卖掉 `Smiley Face`（+5 倍率/人头牌）换 `Sly Joker`（+50 筹码）——后者因为"要求对子"
  拿到 +1.5 契合度反超
- 买进 `Smeared` / `Four Fingers` / `Shortcut`（静态 8.0~8.5）——它们改变牌型判定而
  引擎不实现，真实贡献是 0，却因为静态分高永远当不上"最差的"，把牌位永久占死

**静态兜底**（打分场景构造不出来时，例如牌组为空）：

```text
      v̂(k) = V_tab(k)
           + ⎧ 2     若 |J| < 2
             ⎨ 1     若 |J| < 4               空位加成（纯功能牌封顶 3.5）
             ⎩ 0     否则
           + 2 · 1[ a ≥ 4 且 k 是乘区 ]
           + η(k, τ*)

      η(k, τ) = ⎧ +1.5    若 req(k) = τ        契合专精牌型
                ⎨ −2.0    若 req(k) ≠ τ
                ⎩  0      若 req(k) = ⊥        无牌型要求
```

### §6.1 牌型条件的"软筛"（仅过渡期）

条件型小丑牌的牌型条件原来是 **0/1 硬筛**：

```text
      P̂(cond) = 1   若 contains(τ*, req(k))
              = 0   否则
```

成型之后这是对的（专精对子时"要求同花"的牌确实是废牌）。但**过渡期**不对：
那时还没确定流派，"要求同花"的牌是**有过渡价值**的，硬筛会把它整类误杀。

改成**多视角按权重混合**——不动算分引擎，所以引擎保真度完全不受影响：

```text
      soft = 1 − clamp( lead / L_soft , 0, 1 )
      lead = 最高牌型等级 − 第二高等级

      视角集合:
          views = { τ* } ∪ { τ : level(τ) ≥ F_lvl  或  played(τ) ≥ F_play }
                  按等级、打出次数降序取前 N_soft 个

      权重:
          w(τ*) = (1 − soft) + soft · level(τ*) / Σ_level
          w(τ)  =              soft · level(τ)  / Σ_level        τ ≠ τ*
          （Σ w = 1）

      估值（取代 §6 里的 L 与 Δ）:
          g⁺(c) = Σ_τ w(τ) · max_i  max_{ω ∈ Ω_τ}  S(P_ω, J⊕_i c, τ) / S(P_ω, J, τ)

          Δ_j   = Σ_τ w(τ) · (1/|Ω_τ|) Σ_{ω ∈ Ω_τ} [ S(J,ω,τ) − S(J\{j},ω,τ) ]

      soft = 0 或 无候选  ⟹  views = {τ*}  ⟺  完全回到原来的硬筛
```

**三条边界条件**：

```text
1. 没有任何"另一种可能流派"      → soft := 0   （软筛不生效）
2. lead ≥ L_soft               → soft  = 0   （已经定型）
3. 只作用于小丑牌的买 / 换 / 卖；星球牌与天体包仍用单牌型口径
   —— 那两者的收益绑定在"升的那个牌型"上，混牌型没有意义
```

**`F_play` 这条为什么必须有**：`lock_planet_type = True` 会把所有星球牌砸在专精
牌型上（实测一局只用了 1 张），所以其它牌型**永远到不了 `F_lvl` 级**。只按等级挑
候选的话，软筛就是死代码——第一版实测 31 次买入 0 次触发，那一局的结果与改动前
逐字节相同。过渡期真正的信号是"这个牌型我们**实际打过**几次"。

**为什么不去改条件判定本身**：`_hand_is` 同时被**实际出牌预测**使用，其保真度是
22/22 对齐真机验证过的。让它在非触发时返回部分分，会直接污染出牌决策。
多视角混合把"软"放在**视角层**，引擎照旧输出真值（有测试钉住这一点）。

参数：`soft_gate_lead = 2`、`soft_hand_types = 1`、`soft_level_floor = 2`。

### §6.2 消耗牌的槽位策略

消耗牌槽只有 **2 个**，是整局最稀缺的资源之一。三条规则：

```text
R1 清仓：永远不会用的消耗牌 → 卖（在买包之前）
      junk(c) = 1   若 c 是星球牌且 hand(c) ∉ accepted
             = 1   若 c 既不在 SAFE_* 也不在 TARGETED_* 白名单里
             = 0   否则（含 Wraith：条件性可用，不能当垃圾）
      安全阀：accepted 为空（算不出专精牌型）时 junk ≡ 0
              —— 否则"腾槽"会变成"清仓"

R2 就地使用：`use` 端点在 SHOP 也允许 ⟹ 商店里**先**用消耗牌再买
      好处：早一级早吃等级加成；**腾出槽位**接住下一张星球牌

R3 槽满不拿：包里若是消耗牌而槽位已满 → 跳过
      因为 mod 的 `pack.lua:139-152` 只校验**小丑牌位**，
      消耗牌位没有任何检查 → 硬拿会**静默丢失**（不报错、牌也不进槽）
```

**R1 的因果链**（实测 `tools/slot_trace.py` 逐帧可查）：

```text
The High Priestess / The Emperor 在白名单里 → 机器人会用它们
   ↓ 但它们造出来的是**随机**星球牌 / 塔罗牌
随机星球牌通常不是专精牌型 → 用它是被故意禁止的（分兵）
   ↓ 而机器人**从不卖消耗牌**（所有 Sell 调用点都只传 joker=）
杂牌永久占住 2 个槽（实测 c_neptune 从第 87 步躺到结束）
   ↓
槽满 → R3 只能跳过天体包 → **星球牌供给被自己的垃圾堵死**
```

修这一条之后（20 局、10 倍速、同种子配对）：

```text
              平均底注   最高   通关    星球牌用掉/局   腾槽卖出/局
修复前          3.65      A6    0/20        0.40            0
修复①②③④       3.90      A7    0/20        0.50            0
+ R1 腾槽        4.40      A9    1/20        0.65           1.20

修复前 → 腾槽后：更好 10 / 相同 9 / 更差 1，差 +0.75
```

## §16 主 build 流的思考路径

**现状**：机器人只有一个 build 维度——`committed_hand`（专精牌型）。但一个 build
是**两个维度**：**(打什么牌型) × (靠什么让那些牌得分)**。男爵要 K **留在手里**、
同时打对子；现在只建模了后半句。

计划分四阶段：**前置（牌库可见性）→ 一（识别，只观测）→ 二（接入买牌）→
三（可行性）→ 四（改造与弃牌）**。本节记录**已完成的前置 + 阶段一**。

### §16.1 前置：牌库可见性

```text
可见牌库 = G.deck + G.hand + G.discard + G.play
原版 mod 只导出前两项 ⟹ "牌库里还有几张 STEEL / K" 被系统性低估
```

修法：给 mod 的 `gamestate.lua` 加两个**新增字段**（不动现有键），并把安装流程
扩展成"python 生成打好补丁的文件 → PowerShell 覆盖 + 备份"。
实测 `cards=52 / hand=0 / discard=0 / play=0`，合计 52 ✓。

### §16.2 阶段一：盘点 + 识别（**只观测，不改变任何决策**）

```text
第 0 步 盘点   BuildSnapshot = (牌型 τ*, 等级领先, 牌库构成, 各流派支持度)
第 2 步 转向   support(A) = 阵容成色占比(A) + λ · 牌库投资占比(A)

阵容成色占比(A) = Σ_{j ∈ core(A) ∩ 阵容} 静态值(j) / Σ_{全部 j} 静态值(j)
牌库投资占比(A) = |{牌库中满足 A 的投资特征的牌}| / |牌库|

承诺（带迟滞，"计划"语义而非"描述"语义）：
    没有承诺过   → support ≥ build_min_support 才承诺
    最高即承诺   → 保持
    否则         → 现有计划可见：高出 previous·(1+margin) 才换
                   现有计划暂不可见：新方向自己要 ≥ build_switch_floor
    阵容暂时为空 → 保持承诺
```

### §16.3 阶段一踩到的两个坑（都写进 `build.py` 的模块文档了）

**① 牌库特征必须"会变"。** 第一版用"人头牌占比"，但整副牌恒为 52 张、人头恒为
12 张 → 该信号局局相同，等于没提供信息（实测 10 局 `牌库=52 人头=12` 一字不差）。
改成**投资信号**：牌库里"被改造过"的目标牌（强化/蜡封/版本）——那才是机器人真能
改变、也确实在为某个流派投入的东西。

**② 阵容证据不能用边际贡献，会和阶段二循环依赖。**

```text
人头流要能被识别 → 得看到男爵在贡献
男爵要贡献       → 锚点里得包含"留手的 K"
锚点选哪些       → 由识别出的流派决定          ← 循环
```

所以识别用**静态成色占比**（尺度无关 ∈[0,1]、便宜、不依赖锚点）。
"静态表不准"那条结论针对的是**买卖决策**（它看不出配合），而这里只做流派间的
**相对**比较，不存在那个问题。

**③ 承诺必须是"计划"而不是"描述"。** 第一版 `support < min → None`，实测 11 局
最终全部退回"未承诺"（轨迹 `— → 人头流@16 → 牌型流@38 → —`）——因为机器人买卖
小丑牌很频繁，核心牌一被卖掉承诺就没了。改成"计划"语义后：

```text
                未承诺    平均切换/局
承诺=描述        4/10      1.50
承诺=计划        1/10      1.10        ← 实测 10 局
```

分布：牌型流 3 / 人头流 3 / 经济流 3 / 未承诺 1。

**注意**：这一步**没有改变任何决策**，只是把识别结果写进决策日志的 `build` 字段，
用来验证"流派能不能被可靠识别"这个前提。接入买卖是阶段二。

### §16.4 阶段二：把流派接进决策（两件）

```text
① 买牌按流派加权
     shop_card_value += build_card_bonus · 1[牌 ∈ core(主流派)]
② 改造目标按流派选
     archetype_target_order(主流派, 手牌) 排在算分牌**前面**，算分牌补位
         人头流  K > Q > J            （男爵数手里的 K、射月数 Q）
         钢铁流  优先还不是 STEEL 的   （改造的意义是多造出一张）
         玻璃流  优先还不是 GLASS 的
```

两处都做成**可选参数**（`archetype=None` 即原行为），所以

```text
--set build_card_bonus=0        # 关掉加权（还要传 None 才是完全关闭）
```

**实测（10 局、10 倍速、同种子配对，基线是阶段一那一轮）：**

```text
逐局判定：更好 0 / 相同 9 / 更差 1
共同种子平均底注：本次 4.30   基线 4.60   差 -0.30
流派识别分布不变：牌型流 3 / 人头流 3 / 经济流 3 / 未承诺 1
买入 137 次 vs 基线 143 次；决策内容确实变了，但**很少改变结果**
```

**结论：机制正确、接线正确，但对结果几乎无影响**——和软筛那次是同一个模式。
原因可解释：商店决策的实际瓶颈是**"真实得分增益闸门"**（`G_add ≥ 1.05`）和
静态门槛，`+1.5` 的加分很少能让某张牌跨过它；排序变了之后，后面的闸门往往
还是会把候选滤回原来的选择。

### §16.5 A 方案复核：把加权调到 5.0 也一样

```text
build_card_bonus = 1.5  →  平均底注 4.30   更好 0 / 相同 9 / 更差 1
build_card_bonus = 5.0  →  平均底注 4.30   更好 0 / 相同 9 / 更差 1   ← 逐局完全相同
```

**两轮结果逐局一致**，说明买牌加权**从未翻动过任何一个决策**。§16.4 里观察到的
"决策内容变了"其实全部来自 ②（改造目标排序），不是 ①。这条杠杆可以判定为
**不在关键路径上**。

## §17 确定性早死的成因（在查）

20 局里有 2 局死在**底注 1**（17 / 28 步），3 局死在底注 2，且**同种子逐字节复现**。

### §17.1 先修掉一个把人带偏的日志

`choose_plan_discard` 的"计划不用弃牌 → 直接打"分支：

```python
note(f"已成牌（{best_plan.hand_name}）→ 直接打",
     预估得分=round(best_plan.completed_score),   # ← 报的是**估计牌型**的分数
     够过关=best_plan.completed_score >= state.score_remaining)
return Play(current.indices)                       # ← 实际打的是**当前最优**那一手
```

两者可以完全不同：实测一局日志写"已成牌（High Card）预估得分=15"，而那一手
实际得了 **280**。我为此追了一个并不存在的"19 倍算分误差"。
现在改成报 `current` 的数，并加了一条**不变量测试**钉住它
（"日志报的分数必须等于真正打出去那一手的分数"）。

### §17.2 成因：`crisis > 1` 的赌博规则

```python
if crisis > 1.0:
    expected = best_plan.probability * best_plan.completed_score   # 只算命中那部分
    margin = 0.0                                                   # 门槛归零
```

`crisis = 需要 / (当前一手得分 × 剩余手数)` 是**点估计**——开局用一个随机 8 张
手牌估，系统性偏悲观。一旦越过 1.0，机器人就断定"稳扎稳打也输"，于是门槛归零、
只算命中概率，**越赌越危急**：

```text
step 10  play     危急=1.1x
step 14  discard  危急=1.9x        ← 越赌越糟
step 15  play     只能打：没有弃牌机会了（Two Pair 104）需要=230
step 16  play     只能打：没有弃牌机会了（Two Pair 116）需要=126   ← 差 10 分，失败
```

### §17.3 但这一局"赌"不是主因

手数账算下来：

```text
4 手 × 每手 ~110 分 = 440   <   大盲需求 450
```

也就是说**即使不赌也差 10 分**——根因是**底注 1 的裸分能力不够**：那局商店只买得起
一个 $4 的 Buffoon Pack（拿 The Tribe），剩下 $5 连重摇门槛（$15）都到不了。

所以底注早死是**两个因素叠加**：裸分能力贴着需求线 + `crisis > 1` 时把最后一点
确定性换成彩票。§17.2 那条规则是**可以改**的部分（改用"潜力"而不是"当前一手"
来估 crisis 的修法在很早就提过，一直没做）。

### §17.4 修 crisis 的过程中查出一个**会让游戏崩溃**的 mod 竞态

**症状**：每一轮 30 局 eval 都恰好有 1 局"出错中止"，而且**五轮里都发生在第 14 局
（同一种子 BOT013，最深/通关的那一局）**，日志是
`cash_out: ... Remote end closed connection`。

**根因**（mod 日志）：

```text
functions/common_events.lua:1234: attempt to index field 'round_eval' (a nil value)
Oops! The game crashed
```

`G.STATE` 变成 `ROUND_EVAL` 与 `G.round_eval` 被创建（`game.lua:3315`，在
`Game:update_round_eval` 里）**不是同一时刻**。mod 的 `cash_out.lua` 一看到状态是
ROUND_EVAL 就立刻调 `G.FUNCS.cash_out`，UI 还没建好时游戏索引 nil → **进程崩溃**
（不是报错）。和 `G.buttons` 那类竞态同源，但后果严重得多。

**影响**：每轮 30 局都因此**抹掉最好的那一局**，而且这条竞态在全部历史测量里
一直存在——之前所有平均底注都是**被低估**的。

**修法**（`mod_additions/install.py` 的 `cash_out` 补丁）：把调用改成等
`G.round_eval` 存在的条件事件，另加 600 帧（约 10 秒）兜底。实测：

```text
修前：14/20 就中止，mod 日志有 "Oops! The game crashed"
修后：20/20 跑满，mod 日志**没有任何崩溃**；那一局的失败变成 `pack: timed out`
      （客户端 60 秒超时，**游戏进程仍存活**）
```

修后那一轮 20 局：平均底注 **4.55**、最高 9、**通关 1/20**、出错 1
（分布 A1:1 A2:1 A3:5 A4:2 A5:6 A6:2 A7:2 A9:1）。

**注意**：§17.2 那条 crisis 改动**还没有干净的配对数据**——它的基线那一轮
（用旧口径跑）正好被这个崩溃打断在 14/20。要等修完崩溃之后重跑。

### §17.5 crisis 改动的配对结果（崩溃修完之后重跑）

20 局 × 2 臂，同种子，两臂都跑满 20/20（无崩溃）：

```text
                      平均底注   底注≤2 早死   逐局判定
A 基线（crisis=现状）   4.40      3/20 = 15%      —
B 修复（crisis=潜力）   4.55      2/20 = 10%   更好 3 / 相同 17 / 更差 0
```

**关键的一局**：`BOT008` 从 **A1 r2（17 步就死）** 变成 **A3 r9**——那正是
§17.1–17.3 逐步诊断出来的那一局，说明改动打在预测的机制上，不是碰巧。
而且**没有任何一局变差**（3/17/0），这是本会话里第一个有方向的配对结果。

### §17.6 深局的那次超时：**没修好**，但定位到了真正的位置

修完崩溃之后，两臂各剩 1 局失败，**都稳定发生在第 10 局（同一种子 BOT009）、底注 9**：

```text
13:27 / 14:00 / 14:15   pack: 无法连接 ... （timed out）
```

客户端 60 秒超时，而**游戏进程仍存活**——是挂起不是崩溃。

#### 我先猜错了一次

第一版假设是 `pack.lua` 里"手牌为空时 `G.hand.cards[1].T.x` 恒为 nil，条件永不成立"。
按这个改了 `needs_hand`（没有目标牌就不等手牌），**没有效果**——同一个种子、同一套
小丑牌、同样在第 10 局超时。

于是又加了一道帧计数兜底（900 帧 ≈ 15 秒后回错误）。**也没有触发**：客户端报的仍是
60 秒 `timed out`，说明那些等待事件的 `func` **根本没被调用**，计数器自然涨不到 900。

#### 查 mod 调试日志才看清

```text
14:15:2x  BB.REQUEST   :: play({cards=[1,2,3,4,5]})
          BB.ENDPOINTS :: Init play()
          BB.ENDPOINTS :: Playing 5 cards: J♠, J♦, 9♥, 9♣, 9♦
          （之后没有任何 BB.RESPONSE :: play）
```

**挂住的是 `play`，不是 `pack`。** 而且我数了整份日志里 **188 次 `pack` 调用，
每一次都正常推进了**——所以客户端报的 `pack:` **是误标**。

#### 结论与下一步

```text
✅ 已修并验证：cash_out 的 G.round_eval 竞态（游戏崩溃）
✅ 附带：pack 的两处守卫本身是对的（少等无用的手牌 / 等待事件有超时兜底），
        只是都不是这次的病因——留着当防御
❌ 未修：play 端点会在"Playing N cards"之后不回响应
```

下一步该做的是把同款帧计数超时加到 **`play.lua`** 的等待事件上（那里 `func` 确实在
被调用，兜底会生效），并顺带检查 `select` / `discard` / `next_round` 有没有同样的
无超时等待。**我没有继续改，因为这一次我想先把机制确认清楚再动手**——上一轮
"先猜后改"已经浪费了一次测量。

## §18 牌位与复利：①②③ 三项改动（含一次自我否定的实测）

### §18.1 先做诊断：问题不在"不买乘法牌"，而在"填满并轮换"

100 局日志（`tools/mult_diagnosis.py`、`tools/deck_channel.py` 可复算）：

```text
底注 3：56% 的局手上 0 张 ×Mult
局终阵容：0 张 = 54 局   1 张 = 35 局   2 张 = 11 局

  其中乘法牌 85 次 = 13.7%（牌池基线 21%）  ← 偏少，但只是偏少
  估值 ≤6.5 的非乘法牌 438 次 = 70.6%       ← 真正的问题在这
换牌 363 次 = 3.6 次/局；其中 60 次卖掉的是乘法牌

每局最多改造：STEEL 0.14 张（86/100 局是 0）、GLASS 0.08 张（96/100 局是 0）
```

**牌位只有 5 个，而机器人把它当消耗品用**：70.6% 的买入是廉价填充牌，
每局换 3.6 次牌，产出被反复清掉。

**两处具体机制**（都是读代码确认的，不是猜）：

```text
① 换牌的牺牲品 = min(当前边际贡献)  → 成长型/乘法型必然被判成最差
   男爵手里没 K 时≈0、星座刚买时 ×1.0、绿色丑第一手只是个 +1
② PACK_VALUE["standard"] = 4.0 < pack_threshold = 5.0  → 标准包永远买不到
③ 标准包选牌用 max(sell_cost)  → 按**卖出价**挑，完全看不见强化
```

### §18.2 三项改动

```text
① 复利牌不当换牌牺牲品（strategy.swap_victims，语义集中在一个可单测的函数里）
     有非复利牌可牺牲    → 只在这类里挑
     全队都是复利牌      → 只允许"复利换复利、静态成色更高"的单调升级
     换进来的不是复利牌  → 不允许
     紧急时 / 关掉守卫    → 原行为
   复利牌 = MULTIPLICATIVE_JOKERS ∪ GROWTH_JOKERS（19 张会成长的加法牌）
   注：`j_duo`（×2 倍率）本身就是复利牌，第一版守卫被它绕过去了，测试抓到。

② 廉价填充牌估值随底注递减
     penalty = filler_penalty_per_ante × max(0, 底注 − filler_free_antes)
   复利牌不罚（它现在看着弱但会自己长大）；成色 > filler_value_ceiling 也不罚

③a 标准包按需加价（每缺一张强化牌加 standard_pack_bonus）→ **默认已关，见下**
③b 标准包优先挑强化牌（原来是按卖出价）
```

### §18.3 实测：①② 有效，③a **净负**，所以关掉

10 局 × 3 臂配对（`tools/abc_report.py`）：

```text
                      平均底注   逐局判定              有×Mult@底注5  局终0张×Mult  卖掉乘法牌  换牌/局  改造张数/局
A 基线（三项全关）       5.30        —                    3/7           5           8      5.1      1.9
C ①② 开、③ 关          5.10   更好2/相同6/更差2            6/7           2           0      4.1      0.9
B 三项全开              4.70   更好3/相同3/更差4            3/4           3           2      3.3      2.4
```

**① ② 的机制全部按设计生效**：换牌时卖乘法牌 8 → **0**、×Mult 上线率
3/7 → **6/7**、零 ×Mult 的局 5 → **2**、换牌频率 5.1 → 4.1 次/局。

**③a 是净负的**：打开后每局买 3.4 个标准包（**≈$15/局**），而改造张数只从
0.9 涨到 2.4（+1.5 张），平均底注反而从 5.10 掉到 4.70、逐局从 2/6/2 变成
3/3/4。原因很实在：**标准包里大多是普通牌**，每次只能挑一张，命中率太低，

参数留着（③b 保留——它不花钱，只在真拿到标准包时起作用）。

③ 这个方向本身没错（玻璃 ×2 / 钢铁 ×1.5 确实和 ×Mult 相乘），但**该走塔罗**
（Justice / Chariot），不是标准包——那是一条还没做的路。

这一轮再次说明：**只看平均底注会得出错误结论**。三项全开在结果上"更差"

```text
    平均底注、通关率
```

## §7 天体包的期望估值

```text
      w = |accepted|                    可吃牌型的个数（§8）
      (v, q) = shape(c)                 (展示张数, 可拿张数)

          normal (3, 1)   │   jumbo (5, 1)   │   mega (5, 2)
          数据来自 game.lua:673-680

                                 min(v, w)                C(w, k) · C(P₀ − w, v − k)
      E[Λ] =                       Σ          min(k, q) · ─────────────────────────
                                   k = 0                          C(P₀, v)

      P₀ = celestial_pool_size = 12     星球牌池子大小

      Δ_ℓ = L( ℓ(τ*) + 1 ) − L( ℓ(τ*) )          升一级的得分增幅

      ┌────────────────────────────────────────────────────────┐
      │   R(c) = E[Λ] · Δ_ℓ / ( Φ_S · price(c) )                │
      │        = "每 $1 能买到当前得分能力的百分之几"             │
      └────────────────────────────────────────────────────────┘

      买入  ⟺  R(c) ≥ p₀ · (p_u)^u

      p₀ = pack_gain_per_dollar = 0.01      p_u = urgent_pack_relief = 0.25

命中期望对照:

      (v, q)     w = 1                             w = 2
      (3,1)   1 − C(11,3)/C(12,3) = 0.2500      1 − C(10,3)/C(12,3) = 0.4545
      (5,1)   1 − C(11,5)/C(12,5) = 0.4167      1 − C(10,5)/C(12,5) = 0.6818
      (5,2)                        0.4167        2 · 5/12           = 0.8333
```

**两条由这个式子直接得出的结论**：

1. 锁定在**一个**牌型时（`w = 1`），超级包的 `choose = 2` 用不上 → 它和巨型包
   期望相同却贵 $2，**单位价格最差**。原先三种包用同一个常数 4.5 处理。
2. `Δ_ℓ / Φ_S` 随阵容变强而变大（有 xMult 小丑时，一级加的筹码/倍率会被乘区放大），
   所以**后期星球牌更值钱**——常数值做不到这件事。

### §7.1 供给类优惠券

真正的瓶颈不是"单包效率"而是**星球牌供给**：实测 30 局对子平均只升 1.2~1.4 级，
而对子要到**第 3 级**才能让 γ 越过切换点。所以这两张优惠券按"供给倍数"加权，
而不是给一个拍脑袋的高分。

```text
Telescope —— 天体包**第一张保底**是"打得最多"牌型的星球牌（card.lua:1737）:

      ⎧ min(1, q) + E[Λ]( P₀−1, v−1, q−min(1,q), w−1 )    若 保底牌型 ∈ accepted
E_g = ⎨
      ⎩ E[Λ]( P₀, v, q, w )                                否则
                             ↑ 保底落在我们不吃的地方 → 买了也白买

      普通包 (3,1):  0.2500 → 1.0000    倍数 4.00
      巨型包 (5,1):  0.4167 → 1.0000    倍数 2.40
      超级包 (5,2):  0.4167 → 1.0000    倍数 2.40

      "打得最多"按 played 次数（不是等级）——所以如果我们一直在用别的牌型
      过渡，保底就落不到专精的地方。这个条件必须实判。


Planet Merchant / Planet Tycoon —— 提高商店的 G.GAME.planet_rate:

      planet_rate:  基准 4   (game.lua:1903)
                    Merchant → 4 × 2.4 = 9.6    (card.lua:1895)
                    Tycoon   → 4 × 8   = 32

      倍数 = rate(买入后) / rate(现在)        ← 必须是**增量**：商店货架上那张
                                                还没买，写成"当前值"会得到 1.0

      Merchant（未持有）     9.6 / 4   = 2.40
      Tycoon（已持有 Merchant） 32 / 9.6 = 3.33


优惠券估值:

      ┌────────────────────────────────────────────────────────────┐
      │  V_vch(key) = V_base(key) · min( M_supply(key), M_cap )     │
      │  M_cap = voucher_multiplier_cap = 3.0                       │
      └────────────────────────────────────────────────────────────┘

      v_telescope        6.5 × 3.00 = 19.50
      v_planet_merchant  6.0 × 2.40 = 14.40
      v_planet_tycoon    6.0 × 3.00 = 18.00
      v_overstock        8.0 × 1.00 =  8.00    （不受影响）

封顶的意义：这些优惠券只需要越过 exception_value = 7.5 就能**动用利息本金**
（那才是"优先级"的实际落点——门槛 5.0 它们本来就过），不需要天文数字。
```

**耦合效应**：持有 Telescope 之后，`celestial_pack_gain_per_dollar` 的 `E[Λ]`
从 0.25 变成 1.0 → 同一张天体包的每元增益 ×4 → 机器人会买**更多**包。
所以这一条同时提升了"买券"和"买包"两侧的供给。

## §8 承诺映射（牌型锁定）

```text
      目标牌型序列:
          ⎧ E₁ ⊕ … ⊕ E_r ⊕ T_small     若 ∃ j ∈ J : enabler(j)
      T_tgt = ⎨                            E_i 来自 BIG_HAND_ENABLERS（四指/涂抹/捷径）
          ⎩ T_small                    否则

      专精牌型:
          ⎧ arg max_τ ℓ(τ)                       若 ℓ(τ₍₁₎) > 1 且 ℓ(τ₍₁₎) − ℓ(τ₍₂₎) ≥ λ
          ⎪
      τ*(ℓ) = ⎨ min{ τ ∈ T_tgt : ℓ(τ) > 1 }          若该集合非空
          ⎪
          ⎪ arg max_τ ℓ(τ)                       若 τ₍₁₎ ∉ T_tgt 且 ℓ(τ₍₁₎) ≥ λ_k
          ⎩ (T_tgt)₁                              否则

      λ = commit_lead = 1        λ_k = keep_invested_level = 3
      τ₍₁₎, τ₍₂₎ = 等级第一、第二高的牌型

      可吃牌型（主 + 备）:
          accepted = ( τ* ) ⊕ ( τ† )
          τ† = arg max_{ τ ≠ τ*, ℓ(τ) > 1 } ℓ(τ)        备选：**已经在投入的**

      约束:  γ = γ(τ*)  只依赖 τ*        τ† 不进入 γ
```

**为什么第一条（等级领先即锁定）放在最前**：实测等级会被摊薄到五个不同牌型上
（Two Pair +2、Straight +1、Pair +1、High Card +1、Straight Flush +1），
而对子要到**第 3 级**才能让 γ 越过切换点——等级一分散，"专精小牌型"永远启动不了。
另外这一条还顺带解决了"买一张 `Four Fingers` 就把整个投资方向掀翻"的连锁反应。

## §9 经济算子

```text
      利息保留额（每回合利息 = min(⌊M/5⌋, 5)，即 $25 吃满）:

          ⎧ money_reserve = 4        若 a < 3  或  |J| < 3  或  u = 1
      ρ_res = ⎨
          ⎩ max(4, 25) = 25          否则

      重摇预算（视频：底注1 $10-15、底注2 $8-10，之后只在找关键牌时摇）:

          β_rr = R(a) + surplus_rerolls · 1[ M ≥ surplus_money ]
          R = (3, 2, 1, 1, …) 按底注

          ⎧ max( β_rr , ⌊ (M − money_reserve) / c_rr ⌋ )      若 u = 1
      γ_rr = ⎨                                                  "花得起就一直摇"
          ⎩ β_rr                                              否则

          c_rr = 单次重摇花费

      可重摇  ⟺  ( slot_free > 0 )  或  ∃ j ∈ J : 非永恒(j)
                  ↑ 牌位满了也必须能摇：那正是唯一能换牌的局面

      买补充包 ⟺ |packs| > 0
                 且 v_pack ≥ p_th
                 且 ( M − c ≥ ρ_res  或  v_pack ≥ V_exc )

      天体包走 §7 的 R(c)，不用 v_pack。
```

**"牌位满了不能重摇"是实测踩过的大坑**：判据原来是 `booster_slots_free > 0`，
而补充包货架通常就是满的（两个位子摆两个包）→ 那个值恒为 0 → **整条买包分支
从来没执行过**。同一类错误还有重摇分支要求 `free_joker_slots > 0`。

## §10 自动标定（非人工常数）

```text
      β = discard_bonus
        = clamp( 0.5 · median{ (P_{d+1} − P_d) · log₂(1 + C / S_cur) },  0, 0.5 )
        = 0.1175

      α = discard_aversion
        = clamp( 0.25 · Q₁₀{ (P · C + (1 − P) · M) / S_cur − 1 },  0.1, 0.8 )
        = 0.1762

      做法: 用标准 52 张牌随机发 120 副 8 张手牌（不需要游戏在跑），
            对每副算"弃牌去凑最佳牌型"相对于"现在就打"的相对提升，
            再取分位数。

      Q₁₀ = 第 10 百分位

      为什么用 Q₁₀ 而不是中位数: 相对提升是重尾分布——实测第 10 百分位就有 1.10、
      中位数 5.34（散牌当前分太低，随便凑个牌型都是好几倍）。取中位数的任何比例
      都会顶到上限，门槛就失去意义。
```

初始值随评分公式和权重自动变化，不需要人工重调；之后由 `tools/tune.py`
用真机对局数据继续修正。

## §15 结论：常数与派生量

**11 组式中真正的人工常数**只有：

```text
    γ₀, γ₁, s₀, s₁, B              前后期切换的形状（§4）
    δ_b, δ_s                       买卖门槛（§6）
    p₀, p_u, P₀                    天体包期望（§7）
    λ, λ_k                         牌型锁定（§8）
```

其余全部派生：`α, β` 由 §10 自动标定；`P_τ, C_τ, M_τ, E_τ, L, Δ_j, Φ_S, Δ_ℓ`
全部由 §1 的计分泛函 `S` 算出，与真机得分**同源**——不会出现"规划层算一套、
出牌时算另一套"。
